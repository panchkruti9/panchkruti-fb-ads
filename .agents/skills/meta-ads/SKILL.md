# Meta Ads lifecycle

Use the current root project. Treat **Start manage ads** as authorization to continue the full saved lifecycle. Respect narrower requests, chat-only requests and exact launch or spending authority.

1. Run `meta-ads manage --connected`. Reuse assigned products and existing runs. For a fresh copy, discover setup from connected sources and save private brand policy; ask only for missing business decisions. See [README](../../../README.md).
2. Run `meta-ads next RUN_ID`. Read the returned skill and its practical decision guide, [decision method](references/decision-method.md), [operating knowledge](references/operating-knowledge.md), [policy](references/policy.md) and the applicable [contract](references/contracts.md). The selected skill teaches the work; the lifecycle validates and records its result. Use the returned capability inventory and evidence assessment before choosing an action.
3. Use Shopify/Drive plugins for their evidence. Use GitHub Meta jobs for Meta work: `worker --run RUN_ID`, `execute RUN_ID` and `reconcile` route automatically. Never ask for local Shopify or Drive tokens for connected mode. `operator-check` verifies the actual GitHub environment. Fix ordinary setup using existing authorized connections.
4. Collect current evidence with `collect`, then submit the selected skill with `submit --connected`. Preserve the returned revision. Separate observations from hypotheses. Sparse history calls for a reasoned first test. Check the existing managed campaign before proposing another build. Keep failed strategies and their evidence in the next cycle's context.
5. Continue supported independent work when an optional source fails. A missing thumbnail, unavailable audience option, warning or connector checksum does not justify abandoning the campaign. Use the documented media revision/download fallback. For a genuine required gap, state the precise missing choice or access, ask once, and explain what remains ready and when work resumes.
6. Prepare the exact paused build. Standing management authority covers ordinary launches, strategy, pauses and redistribution within the approved allocation; the operator signs routine work automatically. Ask for the user's actual approval of increased total spending or a completed new agent-designed creative. Legacy runs keep their original policy until explicitly migrated. Read back every Meta mutation and reconcile uncertain writes before retrying. Do not infer new consent from a schedule.
7. After meaningful saved work, link `meta-ads log RUN_ID`. Report **Done**, **Now**, **Next and when**, and **Your action** only when user input is needed. Use product/campaign names in conversation. Say whether an issue is agent-owned, scheduled, or genuinely waiting for the user. Never say nothing is needed while silently waiting indefinitely.
8. Separate operational checks, purchase verdicts and strategy reconsideration. Use actual delivery, qualified exposure, comparable dates, lag and matching coverage; zero matches alone are insufficient. Prepare a documented planned challenger while the control matures. A Learning label alone is not failure. Diagnose the limiting factor before acting and scale only on verified contribution, the strategy's repeatability design and approved headroom. A calendar review date alone does not erase research.

On wake, `manage --connected` imports encrypted Meta snapshots. Review the eligible Meta/Shopify dates once across missed days, then continue the saved route. GitHub can record Meta history while the agent is closed; plugin research and creative decisions require a running connected agent. Do not describe a read-only schedule as a full autonomous agent.

Use [the skill map](references/skill-map.md) for all lifecycle responsibilities. No direct shortcut around saved approvals or exact account scope.

Use `agi_spending` from status and the readable log for the verified AGI start, first delivery and spend since start. A paused build has no AGI start and uses no AGI budget. Keep Meta account counters and limits separate. Do not repeat an unchanged owner question on each wake; continue independent checks and only notify when there is a new result, changed proposal or genuinely new decision.
