# Select useful, actually enforceable delivery

This is the system's operating method. Account settings and current provider capabilities still require readback.

## Separate hypothesis and control

A shopper profile guides the message. It is not a claim that Meta exposes an interest or can identify a personal condition. Start with verified shipping countries and supported controls.

## Broad, warm or lookalike

Broad delivery can be a sensible first test with good offer/message fit. Warm delivery needs a verified relevant audience, recency and purchase objection. Lookalikes need a usable relevant seed and a budget that can answer the comparison. Explain why deferred alternatives add little information now.

## Availability

Read delivery status independently from operation warnings. Deliverable stale or populating audiences can be considered with limitations. Reject integrity restrictions and inactive/failed audiences. Use the exact include/exclude IDs and verify the saved targeting and expansion controls before launch.

## When a feature is unsupported

Do not invent a custom audience or silently claim a suggestion is a hard restriction. State the supported alternative, continue useful preparation and isolate any genuinely necessary capability work. Avoid product-condition names that imply sensitive health targeting.

Read the shared [operating knowledge](../../meta-ads/references/operating-knowledge.md) for source references and evidence limits. The current skill's output schema remains authoritative.

## Applied purchase decisions

Start with serviceable geography and the buying hypothesis. Compare broad prospecting, a usable relevant warm pool and an eligible lookalike seed. Explain why an audience test could change the purchase outcome, what remains constant and which alternatives cannot be funded usefully yet. A condition-related persona is not permission for sensitive targeting.

Verify exact includes/excludes and whether they are strict controls or expansion suggestions. If a website audience is missing, an AUDIENCE recipe can create product-page PageView/ViewContent cohorts or explicitly all-store event cohorts. Purchase and checkout events need all-store scope or a separately verified product-event mapping, not a product-page URL assumption; wait for actual delivery eligibility before using it. Use ALLOCATE for justified existing ad-set funding transfers. Missing/inactive warm pools leave broad delivery available; never invent an audience ID.

Read the [shared decision method](../../meta-ads/references/decision-method.md) for calculations, evidence grades, scenario diagnosis, authority and maintained source links. Preserve a dated observation versus hypothesis distinction in the handoff.
